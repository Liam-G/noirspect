# NUC-003 Unchecked decomposition

**Severity:** high · **Default:** on

A hint splits an input into bits, bytes or limbs, and the circuit checks that
the parts recombine to the input. If a part is not range checked to its width,
the decomposition is not unique: `x = 5` can be "decomposed" as bits
`[1, 2, 0, 0]` (1 + 2·2).

```rust
unconstrained fn bits_hint(x: Field) -> [Field; 4] { /* ... */ }

fn decompose(x: Field) -> [Field; 4] {
    // Safety: bits are recombined below
    let bits = unsafe { bits_hint(x) };
    assert(bits[0] + bits[1] * 2 + bits[2] * 4 + bits[3] * 8 == x);
    bits // no bit is checked to be 0 or 1
}
```

## Fix

Bound every limb to its width. Any of these works:

- return integer types from the hint (`[u8; N]`, `[bool; N]`): the compiler
  range checks integer hint outputs automatically;
- `limb.assert_max_bit_size::<8>()`;
- for bits, `assert(b * (1 - b) == 0)`.

## What the rule looks at

Equality constraints that are a sum of hint values with constant weights plus
an outside value. The width of each limb is the ratio between consecutive
weights (2 for bits, 256 for bytes, 2^128 for a hi/lo split). Every limb but
the top one must be proven to fit that width, by its type, a range check or a
boolean check. The top limb only needs some bound.

For library functions, the rule stays quiet when the unchecked limbs are
returned, because the caller may check them.
