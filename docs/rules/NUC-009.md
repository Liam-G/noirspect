# NUC-009 One-directional bound

**Severity:** medium · **Default:** on

A hint result is tied to its inputs only by comparisons, and every comparison
bounds it from the same side. The result is then never pinned: the prover can
return any value on the unchecked side.

```rust
unconstrained fn sqrt_hint(y: u64) -> u64 { /* ... */ }

fn sqrt(y: u64) -> u64 {
    // Safety: the root does not overshoot
    let r = unsafe { sqrt_hint(y) };
    assert(r * r <= y); // r = 0 passes for every y
    r
}
```

Other common shapes: a `max` hint checked only with `m >= a` and `m >= b`
(any larger value passes), a `min` checked only from above, or a division
checked only with `d * q <= n`.

Pinning the result to one of the inputs does not help if a comparison is
missing. With `(m == a) | (m == b)` and `m >= b` alone, `m = b` passes even
when `a` is larger:

```rust
fn max(a: u32, b: u32) -> u32 {
    // Safety: the maximum is one of the inputs and not below b
    let m = unsafe { max_hint(a, b) };
    assert((m == a) | (m == b));
    assert(m >= b); // m >= a is missing
    m
}
```

## Fix

Bound the result from both sides:

```rust
assert(r * r <= y);
assert(y < (r + 1) * (r + 1));
```

or pin it with an equality and compare it with every candidate, for example
`assert((m == a) | (m == b))`, `assert(m >= a)` and `assert(m >= b)` for a
maximum.

## What the rule looks at

Every constraint that involves both the hint's results and something else.
The rule fires only when all of them assert an `lt` comparison (`<`, `<=`,
`>`, `>=`) with the hint on one side, that side grows with the hint's values
(no hint term with a negative weight), and they all bound the hint in the same
direction. Any equality, or a comparison it cannot orient, keeps it quiet.

**Selection form:** one constraint pins the result to one of several values,
as `(m == a) | (m == b) | ...` asserted true or `(m - a) * (m - b) == 0`, and
every other constraint is a comparison in one direction, but not every
candidate is compared.

It does not fire on hints that take no live inputs (free witnesses by design)
or on hinted indexes (NUC-005).
