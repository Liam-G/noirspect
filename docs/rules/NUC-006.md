# NUC-006 Half-checked sort

**Severity:** medium · **Default:** on

Checking a hinted sort takes two properties: the output is ordered, and it is
a permutation of the input. Checking only the order lets the prover return any
sorted array, for example all zeros. Checking only the permutation lets the
prover return the input unsorted.

```rust
unconstrained fn sort_hint(a: [u32; 4]) -> [u32; 4] { a.sort() }

fn sorted(a: [u32; 4]) -> [u32; 4] {
    // Safety: the output is checked to be ordered
    let s = unsafe { sort_hint(a) };
    for i in 0..3 { assert(s[i] <= s[i + 1]); }
    s // never tied to `a`
}
```

## Fix

Check both properties, for example with a hinted index map
(`assert(s[i] == a[idx[i]])`, plus a check that `idx` is a permutation),
or use a library such as `noir_sort`.

## What the rule looks at

Hints that take an array argument and return an array of the same type.

- **Order without permutation:** a comparison between two output elements,
  and no constraint touching both the output and the input.
- **Permutation without order:** only when the hint's name contains "sort",
  and its outputs are not used as array indexes (an index map is not a
  sorted array).

A multiset check such as matching sums is counted as a permutation check,
even though it is weaker than one.
