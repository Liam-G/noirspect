# NUC-006 Half-checked sort

**Severity:** medium · **Default:** on

Checking a hinted sort takes two properties: the output is ordered, and it is
a permutation of the input. Checking only the order lets the prover return any
sorted array, for example all zeros. Checking only the permutation lets the
prover return the input unsorted.

```rust
unconstrained fn sort_hint(a: [u32; 4]) -> [u32; 4] { a.sort() }

fn sorted(a: [u32; 4]) -> [u32; 4] {
    // Safety: the output is checked to be ordered
    let s = unsafe { sort_hint(a) };
    for i in 0..3 { assert(s[i] <= s[i + 1]); }
    s // never tied to `a`
}
```

The permutation check itself can be too weak:

- **Hinted indices that may repeat.** `assert(s[i] == a[idx[i]])` ties each
  output element to some input element, but with `idx = [0, 0, 0, 0]` the
  output is four copies of `a[0]`.
- **Too few power sums.** Matching the sum and the sum of squares does not fix
  four elements: `{0, 1, 5, 6}` and `{0, 2, 3, 7}` agree on both. A multiset
  of n elements needs the sums of powers 1 to n.

## Fix

Check both properties. For the permutation, any of these works:

- a hinted index map with the indices shown to be distinct: pairwise
  `assert(idx[i] != idx[j])`, or the inverse-map check of the stdlib's
  `check_shuffle` (for each i, a hinted position `p` with `idx[p] == i`);
- a product check `Π (r - s[i]) == Π (r - a[i])` at a challenge `r` derived
  from both arrays (a hash), not a constant;
- the sums of powers 1 to n;
- the stdlib's `sort` and `sort_via`, or a library such as `noir_sort`.

## What the rule looks at

Hints that take an array argument and return an array of the same type.

- **Order without permutation:** a comparison between two output elements,
  and no constraint touching both the output and the input.
- **Permutation without order:** only when the hint's name contains "sort",
  and its outputs are not used as array indexes (an index map is not a
  sorted array).

- **Too few power sums:** order is checked, and every constraint tying the
  output to the input is a power sum `c·Σ s[i]^k` (plus terms free of the
  output), without all exponents from 1 to n.
- **Indices that may repeat:** an integer array from a hint whose n elements
  index every position of an n-element array, with no constraint relating two
  of the indices and no read of the index array at a computed position.

Other multiset checks, such as a single sum when the order is checked, count
as a permutation check even when they are weaker than one.
