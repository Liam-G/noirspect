# NUC-002 Missing remainder bound

**Severity:** high · **Default:** on

A division hint returns a quotient and a remainder, and the circuit checks
`q * d + r == n`, but never `r < d`. Then `(q - 1, r + d)` satisfies the same
check, so the quotient is not unique.

```rust
unconstrained fn div_hint(n: u32, d: u32) -> (u32, u32) { (n / d, n % d) }

fn div(n: u32, d: u32) -> u32 {
    // Safety: q and r are checked below
    let (q, r) = unsafe { div_hint(n, d) };
    assert(q * d + r == n);
    // missing: assert(r < d);
    q
}
```

The Noir compiler accepts this program: both results appear in a constraint
together with an input.

## Fix

```rust
assert(r < d);
```

## What the rule looks at

Equality constraints that contain a product `q * d` and a term `r` with the
same coefficient, where `q` and `r` come from one hint and `d` does not. The
remainder counts as bounded when some `lt` comparison has `r` on the left and
`d` on the right (`r < d`, `d > r`), or a checked unsigned subtraction
`d - r` exists. A bound against another value (`r < n`) or an off-by-one bound
(`r <= d`) does not count.

When the divisor is a constant, the recombination is a decomposition and
NUC-003 applies instead.
