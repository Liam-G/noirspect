# NUC-008 Empty safety comment

**Severity:** info · **Default:** on

The compiler asks for a `// Safety:` comment on every `unsafe` block that calls
unconstrained code. A comment that gives no reason (empty, "safe", "TODO",
"trust me", "n/a") silences the warning without telling a reviewer which
constraints make the hint sound.

```rust
// Safety: TODO
let inv = unsafe { inv_hint(x) };
```

## Fix

Say what checks the hint's results:

```rust
// Safety: inv * x == 1 is asserted below, which pins the inverse
let inv = unsafe { inv_hint(x) };
assert(inv * x == 1);
```

## What the rule looks at

`// Safety:` comments (any case) in the analyzed package's own sources. A
reason that continues on the following comment lines is accepted.
