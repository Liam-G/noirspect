# NUC-001 Constant-only check

**Severity:** high · **Default:** on

A value returned by an unconstrained hint is only ever compared to constants.
The circuit then checks the hint's *claim* ("the signature is valid"), not the
computation behind it, so a dishonest prover can return whatever passes.

```rust
unconstrained fn verify_hint(sig: Field, msg: Field) -> bool { sig == msg * 7 }

fn verify(sig: Field, msg: Field) {
    // Safety: the hint verifies the signature
    let ok = unsafe { verify_hint(sig, msg) };
    assert(ok); // the prover simply returns `true`
}
```

## Fix

Recompute the claim in constrained code, or use the hint only as a witness and
constrain it against the inputs, for example `assert(sig == msg * 7)`.

## What the rule looks at

Every constraint that touches the hint's results. If none of them involves a
circuit input or another hint, the hint is only checked against constants.

It does not fire when:

- the hint has no non-constant arguments (an oracle or free private witness,
  which is unconstrained by design);
- the result is used as an array index (see NUC-005);
- in a library function, the result (or a value computed from it) is
  returned, because the caller may tie it to the inputs;
- two of the hint's own outputs are compared to each other (see NUC-006).

The compiler's independent-subgraph check also catches some of these cases,
but only when the hint result never reaches the circuit's outputs.
